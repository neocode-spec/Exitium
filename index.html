The idea behind Exitium

AI should be a tool you control, not a place you must visit.

Much of today's AI experience happens through websites and cloud services. You open a browser, connect to the internet, submit a request, and wait for a remote system to respond.

That approach is useful, but it is not the only possible approach. Exitium explores local AI: software that uses a model running on the computer itself, so supported conversations and processing do not have to be sent to a remote AI service.

The aim is not to pretend that a small local model can outperform every large cloud model. It cannot. The aim is to make a practical set of AI capabilities available on a wider range of computers, with clearer boundaries around connectivity, control, and privacy.

Exitium is being developed around the idea that powerful software should not automatically require expensive hardware, a constant internet connection, or a complicated setup for every task.

Start with the basics

What does local AI actually mean?

“Offline AI” is not a magical switch that makes every internet-dependent feature work without the internet. It describes where the AI model runs and which parts of the application can operate without a network.

1. The model runs locally

The AI model is stored on your device and uses your computer's available processing resources to generate responses. A supported local session does not need to contact a cloud AI provider for every answer.

2. Your data has a smaller journey

Keeping a task on the device can reduce the need to transmit its contents to an external AI provider. Actual privacy still depends on the application's storage, networking, logging, and optional online features.

3. Offline and online are separate modes

Local conversation can work without internet when the model and its required files are already installed. Web search, downloads, and online update checks still require connectivity.

Important distinction: local inference does not automatically guarantee that every file, memory, log, update request, or optional feature stays local. Exitium's actual network and storage behaviour must be assessed feature by feature.

Planned edition · Agentic Nano

Not only answers.
Small, careful actions.

Agentic Nano is the planned direction for an Exitium edition that can carry out concrete desktop tasks instead of only describing them: opening an application, opening a folder, locating a file you half-remember. It uses the same local model, on the same computer, and it asks before anything that changes your files.

In development — not in the current build

The conversation stays in the app. The actions happen on your PC.

A request such as “open my Downloads folder” or “find the invoice I saved last month” is currently something you do by hand. Agentic Nano is intended to take care of that small piece of work while you stay in the conversation.

The design keeps the AI's role narrow. The application — not the model — decides which actions exist, validates the paths, and performs the operation. The model helps understand the request and explain the result. That division is deliberate: a compact model should not be trusted to invent file paths or run unchecked commands.

Open applications

How a request would be handled

The sequence below is the intended design. Each step exists to keep a small model from acting beyond what it can safely understand.

01 You ask in plain language

No commands or syntax. The request goes to the same local chat you already use.

02 The app matches an action

A fixed, small set of supported actions is checked against your request. Nothing outside that set can be triggered.

03 Paths are validated

The application confirms the target exists and sits inside an allowed location before doing anything.

04 You see the result

The action is reported in the conversation in plain words, including when it could not be completed.

What Agentic Nano will not do

It will not scan your entire drive without permission, run arbitrary shell commands, delete or move files without a confirmation step, control other people's accounts, or work through a long chain of steps unattended. A compact model is unreliable at extended planning, and the design reflects that limitation instead of hiding it.

Why this belongs in a local-first product

File paths, folder names, and document titles describe a person's life. Keeping the matching and the index on the same computer is the point: the assistant can know where things are without that map being uploaded to a service. Allowing a folder for indexing would remain your choice.

How it works

How the AI engine works.

Exitium is the desktop application around the AI experience. The AI engine is the component that generates answers. Separating those two concepts makes the product easier to understand and makes technical limitations easier to explain.

From your message to an answer

In the current development architecture, the desktop interface communicates with a local AI engine running on the same computer, which generates the response.

01 You enter a message

The desktop interface collects your prompt and any supported attached content.

02 Exitium prepares context

The application manages the conversation and prepares the information supplied to the engine.

03 The local engine generates

The engine runs inference using available system resources and its configuration.

04 The answer returns to the UI

Exitium displays the generated response and may store conversation information according to its configured memory behaviour.

Why use a compact AI?

Compact AI systems generally require less memory and storage than much larger ones, although actual performance depends on configuration, context length, runtime settings, and hardware. That makes them worth exploring for older or modest Windows PCs. The trade-off is that a compact system may be less capable at difficult reasoning, long instructions, complex coding, and some image-understanding tasks than larger cloud systems.

Does local AI mean it never uses the internet?

Not automatically. Local inference can work offline once the required files are present, but update checks, downloads, and optional web search need a network connection. The application should make those boundaries clear and avoid describing an online feature as fully offline.

Hardware and performance

Local AI for real computers.

Exitium Nano is aimed at making local AI more accessible. That does not mean every computer will deliver the same speed or support every capability. The software and the machine both matter.

Processor CPU

CPU inference can make local AI possible without a dedicated AI accelerator, but speed varies significantly by processor.

Memory RAM

System memory must accommodate the AI, context, runtime, and other applications. More available memory can improve headroom.

Storage SSD

Faster storage can improve loading time. Sufficient free space is still required for the application files.

Graphics Optional support

Acceleration depends on the runtime, supported hardware, and configuration. A GPU should not be assumed necessary or guaranteed to be used.

What has actually been tested?

The development setup has been tested on a Windows PC with a sixth-generation Intel Core i5, 16 GB of RAM, and an NVMe SSD. This is a development reference point, not a minimum specification or a guarantee of performance on all computers. A public release should include a confirmed minimum specification, recommended specification, and performance expectations after broader testing.

Will it work without internet?

Local conversation can operate without internet when the required application files are installed and available. Downloading the application, retrieving updates, and using online search still require connectivity. Offline operation should be tested after a fresh installation, not assumed from one successful development session.

Privacy by design

Your computer is part of the privacy model.

Running AI locally can reduce reliance on remote services. Good privacy communication also requires being honest about what is stored, what is sent online, and what has actually been verified.

What local-first means here

Exitium's direction is to keep supported AI inference on the user's own machine. That is a useful foundation for privacy, especially for people who want to use AI without sending every prompt to a hosted AI provider.

Optional web search

When web search is enabled, search queries can be sent to DuckDuckGo. Those queries leave the computer. Do not include sensitive information in a search query unless you understand and accept that external service's handling of it.

Updates and downloads

Checking for updates and downloading releases requires a network connection. These activities can contact external hosting services. The final privacy documentation should specify the exact requests made by the released application.

What is not claimed

This page does not claim that the app has undergone an independent security audit, that every network request has been independently verified, or that local storage is encrypted. Those statements require evidence.

A note about privacy and memory

Remembering a previous conversation is different from guaranteeing that every stored item is accurate, secure, or retained exactly as expected. Memory controls, data deletion, storage location, and backup behaviour should be explained in the documentation for the released build.

The long-term direction

A more independent relationship with intelligence.

Exitium begins with a straightforward question: how much useful AI can we bring to a personal computer without making a remote service the centre of every task?

The answer will come from engineering, testing, and improving the experience one release at a time. The project is interested in practical offline AI, compact software, useful memory, and a desktop experience that people can understand.

The goal is not to claim that the work is already finished. It is to build something real, explain what it does, acknowledge what it cannot do yet, and keep improving it.
